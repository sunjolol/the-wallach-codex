## Section 3 — The load-bearing principles this captures

The directives across the user's verbatim message decompose into structural commitments. These are the constraints every subsequent round must honor:

1. **Sabbath-as-spirit, not Sabbath-as-dogma.** Tacitus doesn't run during Sabbath (Sat 12 AM EDT → Sun 10 AM EDT). The discipline is real. But the agent CAN simulate Tacitus runs against the same substrate to verify prompt designs, AS LONG AS the simulation outputs are ephemeral (/tmp only), never written to `tacitus/notebook/`, and deleted after evaluation. The "as if it never happened" is the rule. The principle: discipline serves outcomes, not the other way around. "ACTUALLY operate with DISCIPLINE (but not blind dogma)" is the load-bearing phrase.

2. **The wisdom-as-balance principle.** "Creating a sort of intelligence/wisdom factor through balanced philosophies." The system must have rigor (catalogues, invariants, rules with enforcement gates) AND it must have ESCAPE HATCHES (feature flags, simulation, user override). Without rigor, nothing holds; without escape, the system becomes a tyranny.

3. **The teach-both-directions principle.** "A system that teaches the user (and sort of itself too..)." The substrate (saga + lessons + decisions + catalogues + Tacitus notebooks) IS the wisdom transfer medium. Every round that ships substantive work also adds to the substrate that future co-work + future Tacitus + future projects ingest. The logging IS the teaching mechanism.

4. **Dribbble-as-canonical-design-source.** Explicitly named. Not "interpret screenshots until you can't"; not "any random reference." Dribbble for design discovery. CodePen for verified-working-code. The hierarchy is: Dribbble → identify high-end design → follow link to CodePen → byte-for-byte port. The mental model the user's Round 139 v1-v5 missing taught us.

This is the structural concession the user named — the agent role splits: Tacitus identifies the design problem + suggests search vocabulary; co-work Claude executes the search + ports the result. 6. **Hidden-back-end / front-end-personalization wow factor.** The user explicitly named the UX shape: "blur the lines between where we got the ideas from, purely a back-end operation with a front end presentation that hides its sources for the legitimate personalization-aspect and wow factor."
