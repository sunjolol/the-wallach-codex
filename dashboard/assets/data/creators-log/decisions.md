## Corpus structure
- `knowledge/manifest.csv` is the single source of truth for corpus state. All downstream queries go through it.
- Speaker confidence buckets: High / Moderate / Low / Exclude. Don't reorganize.
- New sources (YouTube, books, podcast) all ingest into the same manifest with `confidence_basis` distinguishing source type.

## Pipeline
- Windows Task Scheduler runs the weekly YouTube refresh (Sundays 7pm). Cowork weekly digest fires an hour later. Both armed.
- Python scripts run user-side, not in this sandbox. Sandbox is for analysis only.
- **No more sandbox-side writes to `manifest.csv`** — only the user's Windows Python writes the manifest. Linux-mount writes have caused corruption in the past.

## Brain

- New brains must outperform the prior version on `evals/` tests to win.

## Design patterns and architectural decisions (begun 2026-06-13 at ~10:15 AM)

- **localStorage as the user-edit layer, JSON files as the canonical source.** Pattern used across Label Check (lcWishlist_v1, lcRegimen_v1, lcRecentScans_v1, lcOutcomes_v1) and Regimen view (rgOverrides_v1, rgManualItems_v1, rgRemoved_v1, rgOutcomes_v1). Canonical files in `memory/` are read-only at dashboard render time; user edits land in localStorage as overrides. Sync to canonical happens via Claude-in-chat updating the source file when asked. This keeps the dashboard fully functional offline without backend, while preserving the "ask Claude to update the persistent record" pattern.
- **Custom confirmation modal with deliberate-acknowledgment checkbox.** For high-friction commits (Add-to-regimen with sparse data), the button is always clickable but a checkbox toggles its label between "Add Anyway" (acknowledged-risk) and "Add Item" (confirmed-decision) plus color shift amber→green. Replaces native confirm() everywhere in the dashboard. Used in 4 commit points + reused for destructive deletes (without the checkbox).
- **Three-path OCR fuzzy correction.** Levenshtein within edit-distance threshold + first-letter Jaccard fallback + suffix match (prefix-eaten) + prefix match (suffix-eaten). All four with first-letter agreement required for the body paths. Conservative thresholds — won't hallucinate replacements when no good candidate exists. Couples with image preprocessing (upscale + gentle contrast + grayscale) and Tesseract `eng_best` model + PSM 6.
- **Self-heal pattern for legacy data.** When data-shape evolves and existing user entries lack the new fields, the render layer derives approximations from whatever signals ARE present rather than demanding a wipe. Demonstrated by HYDRA DNA regimen card pulling topGapFills as nutrient approximations when full label_data is absent.
- **Backburner queue as a discipline.** Task #2 (Edit-item → Label Check tab integration) deferred deliberately because it intersects the tab-consolidation pass the user mentioned wanting later. Pattern: pair related architectural decisions into the same iteration window rather than answering them at different points.
- **Memory + essence as a deliverable.** The user explicitly values the saga/lessons/decisions logging as part of the system. Documentation of *why* each phase happened is a load-bearing part of the architecture — without it, future sessions lose the road that got us here.

- **Tesseract `eng_best` model chosen over `eng`.** ~50MB vs 25MB, 2-3× slower runtime, materially better accuracy. User explicitly OK with the slower runtime: "slower almost makes it feel cooler like the machine is 'thinking' about it." Loading messages updated to match the deliberate feel ("Warming up high-accuracy OCR... → Reading text carefully...").

- **Tab structure decision deferred.** Dashboard now has 7 tabs (Where you stand / The journey / Gaps / WHY-layers / My regimen / Tools / Label check). User mentioned wanting to "condense/re-arrange how it's all categorized later." Tab restructure is queued for the next major iteration and will be informed by which tabs see actual daily use.

- **Brain v2.8 (2026-06-13):** Real-time essence logging. Triggered by user feedback at Phase 4 close — essence-logging had lapsed for most of the 10-hour build day and was batched at the end.
