# Brain v3.11 — Round numbers from the saga (Round 104)

_Round 104. 2026-06-17. Triggered by the user's observation that the main dashboard's journey timeline had silently fallen behind the saga — most-recent history entry showed `round:101 — Honest dietary baseline` (which was actually Round 102's work), and Round 103 was missing entirely._

## What changed

This is a tool-surface + protocol change, not an agent-reasoning-instruction change. `brain/current.md` text is unchanged. The brain version bumps because the discipline this round codifies is one the agent must execute on every saga round close — it's part of the closing-move-atomic protocol the agent follows.

The four-piece structural change:

### 1. `tools/version_bump.py` reads round numbers from `saga.md`

New function `latest_saga_round()` regexes the canonical heading form `^**(date)** Round N` in `memory/essence/saga.md` and returns max(N). The previous `next_round = max(history.round) + 1` heuristic is gone. Round numbers are now READ from the canonical narrative, not invented.

### 2. `version_bump.py narrative-only` for non-version-bump rounds

New CLI form:

```
python3 tools/version_bump.py narrative-only "Summary" [--tacitus-bump v2.X]
```

Records the saga round in versions.json history without changing brain/dashboard versions. The `--tacitus-bump` flag adds a `tacitus_bump` field to the history entry so Tacitus subsystem rounds surface in the journey timeline without polluting `current.*` with Tacitus-specific fields.

### 3. `check_saga_versions_history_match` invariant deployed

New invariant in `tools/invariants.py`. Daily cadence, warning severity. Verifies every saga round in the contiguous tail of versions.json history has a corresponding entry. Catches forward drift within 24 hours. Pre-tracking gaps (Rounds 1-86 retrofit artifacts) are by-design ignored via the contiguous-tail definition.

### 4. Operating-protocols §20 codifies the discipline

The closing-move-atomic principle (§1) extends explicitly to the saga↔versions surface. Every saga round close invokes `version_bump.py` — even for narrative-only rounds. The protocol clause: *"The journey timeline is the user-visible projection of saga round history; missing entries mean visible staleness on a load-bearing surface."*

## What the agent does differently

When closing a substantive round:

1. Append to `memory/essence/saga.md` (and lessons.md / decisions.md as applicable).
2. Invoke `tools/version_bump.py` in the same patch:
   - Brain or dashboard bumped? → `version_bump.py brain|dashboard minor|major "Label"`
   - No main bump but Tacitus changed? → `version_bump.py narrative-only "Summary" --tacitus-bump v2.X`
   - Neither? → `version_bump.py narrative-only "Summary"`
3. The script reads the latest `Round N` heading from saga and uses that number.
4. The script atomically writes versions.json + propagates to dashboard.
5. Run the audit; verify `saga_versions_history_match` passes.

The discipline is codified at the protocol layer so the agent doesn't have to remember it round-to-round — §20 is the call-out.
