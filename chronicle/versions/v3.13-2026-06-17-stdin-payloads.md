# Brain v3.13 — Stdin payloads, no shared tempfiles (Round 106)

_Round 106. 2026-06-17. Triggered by the cross-run tempfile collision the vitality-check task itself surfaced: the morning audit's `/tmp/sentinel.json` content silently bled into the afternoon vitality task's write to `tacitus/sentinel.json`. safe_write's verify-read caught it; the agent restored via a PID-scoped tempfile and flagged the SKILL design as the upstream cause._

## What changed

Tool-surface + protocol change. `brain/current.md` text is unchanged. The brain version bumps because the discipline this round codifies governs SKILL design and write primitives across the project.

### 1. `tools/safe_write.py` accepts `--payload-stdin`

New CLI flag for `append` and `rewrite` subcommands. Reads payload from stdin instead of a filesystem path. Mutually exclusive with `--payload-file`. The Python invocation pattern:

```python
import subprocess, sys, json
payload = json.dumps(obj, indent=2, ensure_ascii=False) + "\n"
subprocess.run(
    [sys.executable, 'tools/safe_write.py', 'rewrite', target, '--payload-stdin'],
    input=payload, text=True, encoding='utf-8', check=True
)
```

Zero filesystem state in the write path beyond the destination file itself. Safe under concurrent SKILL invocations by construction. Cross-platform.

### 2. `logging-vitality-check` SKILL prompt updated

Both write paths (lapse detected + no-lapse activity update) now use the stdin pipe pattern. The hardcoded `/tmp/sentinel.json` literal is gone. HARD CONSTRAINTS section adds explicit guidance: *"NEVER use a hardcoded `/tmp/<bare-name>.json` path for safe_write's payload — stdin pipe ONLY (or `tempfile.mkstemp()` if a tempfile is genuinely required)."* Updated via `mcp__scheduled-tasks__update_scheduled_task` since SKILL files live outside the project repo at `C:\Users\Light\Claude\Scheduled\<task>\SKILL.md`.

### 3. Operating-protocols §22 codifies the anti-pattern

Bans hardcoded `/tmp/<bare-name>.<ext>` literals in SKILLs. Bans bash `$$` PID expansion in non-bash contexts. Bans tempfile-name reuse across SKILL invocations of the same task. Documents the preferred pattern (stdin via `--payload-stdin`) and the fallback (`tempfile.mkstemp()` with O_EXCL). Cross-platform note covers Windows + Linux + Mac. Detection is human-vigilance + post-incident analysis since SKILL prompts live outside this repo.

## What the agent does differently

When designing or reviewing a SKILL prompt that needs intermediate write state:

1. **Default to stdin pipe** via `--payload-stdin`. Python subprocess pattern is in §22 verbatim.
2. **Fallback to `tempfile.mkstemp()`** only when payload size genuinely demands a filesystem path. Never use a hardcoded bare-name.
3. **Audit existing SKILLs** at any reasonable opportunity (catch-up, weekly review, when touching a SKILL for unrelated reasons) for the anti-pattern.
4. **Surface the anti-pattern** if found in any new SKILL prompt the user proposes or creates.

The discipline applies symmetrically to project tools that need inter-process payload handoff.

## The principle underneath

Round 45 → Round 104 → Round 105 → Round 106 form a progression: shared mutable state across system boundaries drifts; the cure is one canonical source per surface plus a verifier or eliminator of the redundant state. Each round names a more-specific instantiation:

- **Round 45:** versions.json as single source of truth + propagator. Closed three-banner-pill drift.
- **Round 104:** saga.md as canonical source of round numbers + saga↔versions invariant. Closed saga→versions drift.
- **Round 105:** vitality-findings.jsonl as canonical persistent log + in-session re-check + invariant. Closed audit-overwrites-vitality drift.
- **Round 106:** stdin payloads + §22 anti-pattern documentation. Closed shared-tempfile drift in SKILL prompts.

Each round took a specific failure (often surfaced by the user or by defense in depth) and closed the upstream structural surface. Defense in depth caught the failures; structural fix removed the need for the safety net on those specific surfaces.

## The drift-surface audit discipline (new in v3.13)

When adding any new subsystem or new scheduled task to the project, audit at addition time for shared-mutable-state surfaces the addition introduces (sentinel files, tempfiles, embed projections, version trackers, log surfaces). Design the defense (canonical-source + verifier + eliminator pattern) in the same round as the addition. Don't wait for the drift to surface in production. This is the meta-discipline the four-round progression named.

## Defense in depth, named

When safe_write's verify-read or any invariant catches a failure, the response is NOT "great, the defense worked." The response is **"what upstream surface should be closed so this catch isn't needed next time?"** Round 106 instantiates this: verify-read caught the cross-run collision; Round 106 eliminated the surface so verify-read doesn't have to catch it next time. Defense in depth continues to exist as the safety net for unforeseen failure shapes; the goal of every structural-improvement round is to make the safety net redundant for known failure families.
