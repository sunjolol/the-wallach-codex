## What changed

Brain version bumps because three structural changes affect every future round that executes:

### 1. `tools/safe_write.py` — auto-rollback on dashboard.html writes (Cure A)

After every successful write to `dashboard/dashboard.html`, `safe_write` invokes the cheap discipline invariants (`raw_key_surfacing`, `cross_iife_bare_refs`). On CRITICAL-severity failure, the swap reverts atomically via a captured pre-swap snapshot; `SafeWriteError` raises with a descriptive message. On warning-severity, the write lands but prints loudly. Honors `SAFE_WRITE_SKIP_DISCIPLINE=1` env var for documented emergencies.

The "violation can't ship to this surface" property is now structural for dashboard.html. Future surfaces with cheap discipline invariants gain protection by adding their path to `_should_run_discipline_checks(path)`.

### 2. `brain/current.md` — Phase D in catch-up trigger (Cure B)

New Phase D between Phase B (catchup seal) and Phase C (response ordering): run `python3 tools/invariants.py` (full manifest) at session start. The integrity briefing's FIRST line item surfaces any failures: *"Invariant manifest: X/Y passing. Failures: <name>(severity, msg)..."* Catch-up no longer only surfaces yesterday's audit-sentinel result — it surfaces TODAY's live state. Known-transient failures (Tacitus modes not yet fired between midnight and 5:18 AM) get noted as transient rather than treated as blockers.

Also new in catch-up Phase C: item 5 — lesson-pinning chat declaration. When the user picks substantive work, the agent's next chat message MUST open with *"Pinning lessons relevant to this work: [#citations]. Will check against these before each substantive write."* The chat transcript captures the trail.

### 3. `tacitus/prompts/cura.md` + `memory/claude-best-practices.md` (Cure C)

Cura graduates from 4-sub-check to 5-sub-check architecture. New Translation-quality Phase-1 sub-check audits documented disciplines against `memory/claude-best-practices.md` — a manually-maintained reference standard with §1-§10 principles for writing Claude-readable rules (anchor sentence, Generalizable: prefix, mechanizable pattern citation, failure family naming, brevity, imperative voice, paired invariant citation, concrete examples, user-quote tagging, jargon explanation).

Rotation discipline via `tacitus/translation-audit-cursor.json`: Cura samples 3-5 entries per night that have NOT been audited in 14 days, oldest-first. Cap of 1-2 translation-quality LANDs per night prevents flooding during the initial cleanup phase (lessons-vault has hundreds of historical entries written before the meta-principles existed).

The sub-check's output is RICHER than the other four — each candidate includes verbatim current text + proposed rewrite + principle citations. The structural answer for non-mechanizable lessons: reference standard + periodic audit + concrete rewrite proposals (not abstract critiques).

### 4. `memory/operating-protocols.md §25` — lesson-pinning sub-section

§25 (added Round 135) gains a sub-section codifying the chat-declaration form of lesson-pinning. Before substantive code work in any session: one-line declaration in chat citing the 3-5 most-relevant recent lessons. Lightweight, no file overhead. Future rounds may upgrade to file-based pins (`memory/session-pins/`) if the chat-only form proves insufficient.
