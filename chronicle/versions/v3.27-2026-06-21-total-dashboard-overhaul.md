# Brain v3.27 — Total dashboard overhaul

_2026-06-21 Sunday. Round 160-161 spans the largest single architectural shift in the project's life: the dashboard moves from a 3.1MB / 22k-line monolith with embedded teal CSS + IIFE-style JS to a strangler-fig-migrated modular system with a sealed design vocabulary, native ES-modules-via-TS-source, and zero external runtime dependencies after Tesseract in-housing. All 6 dashboard surfaces (Coverage workspace, Regimen workspace, Scanner workspace, Knowledge drawer, Journey drawer, Command Palette ⌘K) now ship on the new design system. Dashboard works offline from `file://`._

## The arc

**Round 160 — Phase 0 design-system foundation.** Sealed `design-system.css` as single source of visual truth. 5 in-housed font families (SIL OFL 1.1, no Google Fonts), 28 codepen design references captured under `knowledge/design-wisdom/`, full token vocabulary (paper · ink · accent · tech · status · typography · spacing · motion · z-index), button + card + chrome primitives. Three new invariants (warn-mode initially): `check_no_external_style_resources`, `check_design_system_hash_integrity`, `check_design_system_write_protection`. Feature flag `design_system_enforcement` ships at `warn`; promotes to `error` once shipping criteria met (this round meets them).

**Round 161 — strangler-fig migration.** User explicitly mandated: "WE'RE STARTING FROM SCRATCH AGAIN... ALWAYS USE PROPER, MODERN SOFTWARE ENGINEERING/CODING/PROGRAMMING/ENGINEERING/FILE STRUCTURING STANDARDS." Architecture sub-phases:

- **R1·A (audit + scaffolds + data extraction)**: audited 3.1MB legacy file (4,250 CSS lines + 8,955 JS lines + 285 §31 chokepoint markers + 1,530 Round-archaeology comments + 135 DOM IDs + 89 OCR hits). Extracted 8 JSON + 5 markdown data blocks to `dashboard/assets/data/`. Set up TS + esbuild toolchain (`tools/build-dashboard.sh`, `tsconfig.json` strict mode, `package.json`). Created 16 TS module scaffolds (4 core + 5 state + 6 views + main.ts) with JSDoc-typed export stubs. Hand-wrote initial `dist/main.js` (sandbox can't reach npm). Wrote `dashboard/ARCHITECTURE.md`.
- **R1·B (skeleton swap)**: rewrote `dashboard.html` from 3.1MB monolith to 2.5MB slim shell (no embedded CSS, no embedded JS, 3 `<link>` + 2 `<script src>` loads). Old JS verbatim-parked to `assets/js/legacy-dashboard.js` (492KB, 36 §31 markers preserved). Old CSS verbatim-parked to `assets/styles/legacy-dashboard.css` (172KB). New `assets/styles/dashboard.css` provides app-shell grid + drawer slots + scrollbar + animation primitives only. 4 invariants updated to scan both `dashboard.html` + `legacy-dashboard.js` during migration window. Google Fonts CSP entries removed. Build-freshness invariant added.
- **R2 (Coverage workspace)**: implemented `core/storage.ts` + `core/events.ts` + `state/coverage.ts` + `views/coverage.ts`. Periodic table renders 92 tiles in 6 sections (Minerals 61 · Vitamins 16 · Aminos 12 · Fatty Acids 3 — 3-tier mineral split slots ready for when trace-minerals data arrives). Comprehensive periodic symbol map (Al · As · Ba · ... · Zn · Zr · ω3 · ω6 · ω9). Per-tile detail flyout (polish pass) replaces legacy `showEssentialDetail` bridge. Tile categories: cream gap / green covered / accent-wash aggregate-vehicle.
- **R3 (Regimen workspace)**: §31 chokepoint discipline becomes architectural. 5 chokepoint helpers (`persistRegimen`, `saveRgOverride`, `saveRgManual`, `saveRgRemoved`, `saveRgUserGoals`) implemented as native TS in `state/regimen.ts` with bridge installation that overwrites `window.*` at boot. Cross-IIFE legacy callers now route through new module. Bare-name calls inside IIFE still hit IIFE-local defs (intentional — "re-theme don't rewrite logic"). Drop-zone upload + paste handler bridge to `window.lcScanImage(dataUrl)` (new function added to legacy that does runOcr → parseOcrText → scan in one call, dispatches `lcscan:progress` CustomEvent for progress UI).
- **R5 (Knowledge + Journey + Command Palette)**: 3 overlay surfaces. Knowledge drawer (600px, 4 tabs: Corpus / Essentials / Products / Doctrine, live search filter). **Polish pass.** Font woff2 → ttf cleanup (16 woff2 refs stripped from sealed design-system.css). Knowledge search live filter across all 4 tabs. Regimen cart actions wired to legacy bridges. Scanner drop-upload + paste + Tesseract bridge. Journey LOG EVENT inline form with severity picker + note + tags. Coverage per-tile detail flyout (native, replaces legacy bridge).

**Tesseract in-housing.** User-flagged architectural inconsistency: docs said "fully portable" but OCR depended on `cdn.jsdelivr.net`. Honest fix: wrote `tools/vendor-tesseract.js` (Node script, fetch-based) that downloads ~22MB of Tesseract files (tesseract.min.js + worker.min.js + 2 WASM cores + eng.traineddata best-accuracy variant) into `dashboard/assets/vendor/tesseract/`. Patched `loadTesseract` + `runOcr` in legacy to point at local paths. CSP fixes: `worker-src 'self' blob:` (Tesseract worker via blob URL), `wasm-unsafe-eval` (WebAssembly.instantiate). 4-year-portability promise restored: open dashboard on a plane, scanner works.
