# Brain v3.24 — Eden — sealed catalog architecture (Round 157)

_2026-06-20. Saturday evening continuation. Introduces Eden — a sealed, cryptographically-anchored catalog as the single source of truth for every product recommendation surface in the dashboard. Cures the namespace-conflation root cause behind the accumulated late-Round-156 bug cluster._

## Why Eden

Round 156's "small spot fixes" exposed a structural problem: three overlapping namespaces (`stk_*` legacy regimen IDs, `scan_*` recent-scan IDs, ad-hoc embedded HBSP/goal items) all pretended to be the same thing depending on the surface reading them. Every fix to one surface risked desyncing another. Eden replaces all three with one canonical catalog and three thin derived embeds.

The user articulated the security requirements explicitly: byte-for-byte truth verification, no silent failures, agent (Claude) MAY NOT modify the catalog or golden hash through prompts — only the user, manually, with the file-system invariant guarding against discipline drift.

## What Eden is

A new top-level `eden/` directory holding:

- `eden-catalog.json` — canonical sealed catalog (201 products, 18 goals, HBSP tier list, exception rules). USER-WRITTEN only.
- `eden-catalog.golden.sha256` — SHA-256 truth anchor. USER-WRITTEN only (regenerated via `eden_seal.py`).
- `SCHEMA.md` — strict schema spec (EDEN-LOCKED-<slug> ID pattern, required fields, validation rules).
- `README.md` — architecture doctrine + invariants + workflow.
- `tools/eden_verify.py` — read-only verifier (PASS / FAIL / BOOTSTRAP, exit 0/1/2). Agent MAY run.
- `tools/eden_seal.py` — user-only golden-hash regen, append-only `seal-history.log`. Agent MAY NOT run unprompted.
- `tools/eden_build.py` — derives the 3 dashboard embeds from canonical catalog. Agent MAY run.
- `tools/eden_bootstrap_from_existing.py` — one-time migration tool (now retired in normal operation).
- `derived/` — generated embeds for review (regimen-label-lookup.json, goal-recommendations-data.json, regimen-base-data-recommended.json).

## Invariant manifest changes (net +3 critical)

| Action | Invariant | Cadence | Severity |
|---|---|---|---|
| Added | `check_eden_hash_integrity` | daily | critical |
| Added | `check_eden_embeds_match_canonical` | daily | critical |
| Added | `check_eden_write_protection` | daily | critical |

`eden_hash_integrity` re-computes SHA-256 of the canonical catalog at every audit and compares byte-for-byte against `eden-catalog.golden.sha256`. No silent failure — if the file is missing, malformed, or drifted, the invariant says so explicitly.

`eden_embeds_match_canonical` confirms all Eden-derived dashboard embeds carry the same `eden_version` stamp as the canonical catalog. Catches stale derived embeds after a user-approved seal.

`eden_write_protection` scans `memory/memory-change-log.md` for any line mentioning a write to a protected Eden file (`eden-catalog.json`, `eden-catalog.golden.sha256`) without an explicit `(USER-WRITTEN)` or `bootstrap migration` marker. This is the cross-session enforcement of the "user-only writer" rule — Claude cannot accidentally violate it without being caught at the next audit.
