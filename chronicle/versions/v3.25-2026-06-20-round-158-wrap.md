## What changed at the dashboard surface

**Chunk A — Dose split.** Quick edit modal's single free-text dose field replaced with two number inputs: Dose amount + Times per day. Both drive a derived `scaling_factor` that flows into all nutrient-math surfaces: Periodic Table coverage, slot stats essentials %, per-card essentials contribution badges, scaled nutrient breakdown panel. Live multiplier preview updates per keystroke; persists on `change` (blur/Enter) — no Save click needed for dose tweaks.

**Chunk B — Scaling alignment.** `getItemEssentialContributions` + nutrient breakdown panel both now honor `scaling_factor`. Pre-fix the Periodic Table was scaled but per-card badges weren't — visible inconsistency once dose was modifiable. `amountMg` field returns scaled values now.

**Chunk C — Card UX restructure.** User's design: inline Dose + Per Day inputs on every card body; action row simplified to 2 primary buttons per kind. Recommended cards: `[Details] [Add to Regimen]`. Regimen (supplement) cards: `[Details] [Remove]`. Quick edit + Full edit retired entirely. Details expansion no longer holds dose inputs — only nutrient breakdown + (for Recommended) tagline + (for Regimen) Name+Notes form + Outcome log. New `rg-btn-primary` CSS: flex-1-1-auto, 130px min-width, 10×18px padding, 8px radius, hover-lift. New `renderRegimenTabPreservingState()` wrapper captures expanded card IDs + scrollY + focused-field selection range and restores after re-render — used by inline-dose handlers so editing doesn't collapse the card or jump the page.

**Chunk C+ — Null-ref cascade cure.** Two unguarded `card.querySelector('.rg-edit').onclick = ...` and `.rg-remove.onclick = ...` survived the button-removal refactor. forEach propagates exceptions from the callback, so the loop stopped at the first card and every subsequent card lost ALL its handlers including Details toggle. Cure: null-guard both + per-card try/catch around the forEach body that logs `console.error` with the failing card's ID without re-throwing. Promoted to lessons.md as a doctrine for any UI restructure that removes elements.

**Chunk D — Remove semantics.** For adopted recommendations (`kind=supplement && _adopted_at`), Remove now calls the old Unadopt logic (clear kind override + _adopted_at + _adopted_snapshot, move back to Recommended). Modal copy updated to "Move back to Recommended?". Scanner-sourced label items keep hard-delete; manual items keep soft-delete. Matches user's stated design: "Remove - does the same thing as Unadopt".

**Chunk E — HBSP restore button (Eden-aware).** Pre-fix the empty-state detection had a hardcoded `DEFAULT_REC_IDS = ['stk_BTT_2_5_Canister', 'stk_Beyond_Osteo_FX_Liquid', 'stk_Ultimate_EFA_Plus']` allowlist from the pre-Eden era. After Eden migration HBSP IDs are `EDEN-LOCKED-*` — none matched, so even when HBSP items were in rgRemoved, the restore button never surfaced. Second cause: HBSP that had been Adopted lives in Regimen via `rgOverrides[id].kind === 'supplement'` — the old detection only looked at rgRemoved, never at the override layer. Cure: detection now reads HBSP IDs dynamically from `REGIMEN_BASE_DATA.recommended` (Eden-derived, self-updating); checks three branches (rgRemoved, kind-override != recommended, legacy stk_*/goalrec_* in rgRemoved); restore click clears both rgRemoved entries AND any kind overrides for those IDs. Auto-clearing user goals on restore was retired (surprising side effect).

**Chunk F — Truncation recovery (twice).** Hit silent EOF truncation on dashboard.html twice during this round; `tools/dashboard_integrity.py restore` healed both via SCRIPT_BLOCKS canonical-rebuild path + EOF tag append. No data loss. Doctrine §17 holding.

## What changed at the protocol/lesson/decision layer

**Lessons (2 new at memory/essence/lessons.md):**

1. **forEach exceptions propagate; null-guard every querySelector handler binding after a UI restructure.** When a forEach callback throws, the loop stops — every subsequent iteration is skipped. Signature to grep for during reviews: `card.querySelector('.xxx').onclick =` (unguarded `.onclick` on a querySelector result). Should always be `const el = card.querySelector(...); if (el) el.onclick = ...`.

2. **After a data migration every hardcoded ID allowlist must be re-derived dynamically OR re-audited explicitly.** HBSP restore button died silently after Eden migration because of stale stk_* allowlist. Where possible, derive allowlist from canonical source at runtime. Where impossible, add a regression test or invariant. Round 158 chunk E fixed this for one site; codebase sweep for other latent post-migration ID hardcodes filed for future cleanup.

**Decisions (2 new at memory/essence/decisions.md):**

1. **Per-card try/catch as render discipline (Pattern E candidate).** Every per-item render loop that binds event handlers gets a try/catch around the callback body. The catch logs `console.error` with the item's identifying key but does NOT re-throw. Currently 1 instance (bindRegimenCardActions); promotion to verified-patterns catalog pending 1 more independent use site.

2. **Additive UX moves, not replacive.** When moving UI affordances, the OLD location should either (a) be replaced with the new path's surface (link/breadcrumb), or (b) be removed simultaneously with the new path being made obvious. Empty UI is worse than busy UI — users wonder "where did it go?". The dose-input move (modal → card) got a one-line "Dose is on the card itself" note; the Quick edit/Full edit retirement was paired with the renamed Add to Regimen CTA on cards.
