## What v3.9 adds

Together: the structural answer to "detect what could be going wrong" without relying on human vigilance.

### The new tooling

**`tools/invariants.py`** — declarative manifest of 13 invariants (11 daily + 2 weekly) on adoption. Each entry has `name`, `description`, `check_fn`, `truth_anchor`, `severity` (`critical` / `warning` / `info`), `lesson_ref`, `cadence`. Adding a new invariant is appending an entry; the runner picks it up automatically. The promotion gate (operating-protocols.md §18) makes adding an invariant a closing-move-atomic requirement when a new pitfall is codified.

**`tools/system_audit.py`** — the runner. Walks the manifest, runs every check, writes a structured report to `memory/system/audit-{YYYY-MM}.md`, updates `memory/system/audit-sentinel.json`. Composes the existing 16-check `tools/dashboard_integrity.py` as one invariant — the two layer cleanly without duplication. All writes via `safe_write` (atomic, verified). The audit's own sentinel is the meta-check: if the audit itself crashes, the sentinel doesn't update, and the catch-up trigger hard-wraps the next session via brain step #4.

**`tools/canaries/`** — probe directory. Currently one canary (`safe-write-probe.txt`) that the audit rewrites each run with a fresh timestamp + nonce, then reads back via `os.read` (bypassing any Python text cache). If safe_write itself is broken, this catches it before any other invariant runs.

**`memory/system/`** — system audit's own folder. Owns `audit-sentinel.json`, monthly `audit-YYYY-MM.md`, `known-good-hashes.json`. The truth anchor for append-only invariants.

### Tacitus' new role: meta-auditor

Per the user's Risk 3 idea, Tacitus' 5:05 AM session now reads the previous day's `memory/system/audit-{YYYY-MM}.md` and reflects on whether the audit is catching what it should. He may propose new invariants in his notebook (tag `[invariant-proposal]`). The user reviews proposals during co-work and promotes them to `tools/invariants.py` themselves. Tacitus' write boundary stays as it was — `memory/tacitus/` only, never `tools/` or `memory/system/`. His READ surface expanded to include `memory/system/`; his WRITE surface unchanged. The loyalty covenant from Round 69 stays intact.

### New doctrine principle 11 — Truth-anchored invariants

Every check must pin to an external truth source that can't itself drift. Stale-to-stale equality (the Round 73 trap) is not truth. Invariants in the manifest declare their `truth_anchor` field explicitly so future reviewers can challenge the pinning logic. Valid anchors: committed hashes (versions.json history), deterministic recomputation, primary-source files, user-confirmed snapshots, low-level system reads (os.open + os.read).

### New protocol §18 — Lesson → invariant promotion + sentinel-pair requirement

Two-part rule:

**(a) Lesson → invariant promotion.** When a new pitfall lands in `memory/essence/lessons.md`, the SAME PATCH must add a corresponding invariant to `tools/invariants.py` that would catch the next occurrence. If a lesson can't be automated, it explicitly states why (residual human-vigilance dependency).

**(b) Sentinel pair-check requirement.** When a new status-of-X file is introduced (`.status.json`, last-run markers, completed flags, anything that asserts "this happened"), the same patch must introduce an automated cross-check verifying the sentinel's claim against the artifact it purports to describe.

Together they form the structural discipline: lessons can't accumulate as memorials, sentinels can't accumulate as unverified claims. Each new pitfall generates its own detector. Each new sentinel generates its own cross-check.

### New brain pitfalls (3 added in current.md)

- **Cross-platform Python discipline (Round 74).** Always `encoding='utf-8'` on text-mode `open()`. Avoid `%-I` strftime (glibc-only). Use `datetime.now(tz=...)` not `utcnow()`. Use `sys.executable` not literal `"python3"` in subprocess. Use `pathlib.Path`. Five rules; future tool files violate them at risk of Windows-crash on first audit run.
- **The audit pays for itself on day one (Round 74).** First real audit run caught FIVE distinct real issues: brain-version-embed drift, cp1252 crash on Windows, `%-I` strftime crash, missing `#citation-popup` HTML element, missing `id="cp-eyebrow"` attribute. Each would have shipped silent. Lesson: the audit's invariant count is the project's structural-protection health metric.
- **Self-referential parse confusion (Round 74).** When error messages containing quoted parse-error text land in structured fields (e.g., `last_lapse_reason` in a sentinel.json), the same parser re-reading can transiently misinterpret. Discipline: structured fields hold structured data; error prose goes in sidecar plain-text files.
