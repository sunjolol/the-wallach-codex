## What v3.8 adds

A new Tacitus-write-integrity protocol (operating-protocols.md §16) and a brain-level enforcement step that surfaces sentinel-content drift as a hard-wrap on every session start. The shape is five layers of defense-in-depth — any single layer can fail; the net catches what individual vigilance won't.

### Layer 1: Tacitus SKILL.md write order rewritten

`C:\Users\Light\Claude\Scheduled\tacitus-autonomous-reflection\SKILL.md` — the "WHERE TO WRITE" section replaced with "WRITE ORDER (MANDATORY — DO NOT REORDER)". Five steps:

1. **Notebook entry FIRST** via Bash tool with heredoc. Edit tool is FORBIDDEN for this write (known silent-truncation pattern).
2. **Read-back verify** by grepping for the session header line just written.
3. **On verification failure**: write a `[FAILURE]`-tagged entry naming what happened; EXIT WITHOUT updating sentinel.
4. **Sentinel + `.status.json` update LAST**, only after readback succeeds.
5. **Final cross-check**: notebook contains today's session header AND sentinel date matches today AND `last_reflection_date == today`.

`[quiet]` entries follow the same order — skipping the write isn't an option, because the audit treats an unmoved sentinel as a failed run.

### Layer 2: operating-protocols.md §16 codifies the order

New section: "Tacitus write integrity — content-before-status, verified, never silent (Round 73)." Encodes the rule as project-wide protocol so it survives skill-file edits. Cross-references doctrine §1 (no silent failures), §2 (defense in depth), §4 (atomic operations).

The principle in one line: **content lands before status; status is verified against content; mismatch is loud, never silent.**

### Layer 3: Daily audit at 6:40 AM EDT with sentinel-vs-content drift check

Daily audit task moved from 8:30 AM EDT → 6:40 AM EDT (cron `40 6 * * *`, per user direction in Round 73). The audit now runs a HIGHEST-PRIORITY Check 2 — Tacitus sentinel-vs-content drift:

  - Read `.status.json.last_reflection_date` and `last_reflection_time`.
  - Grep the current-month notebook for today's session-header line.
  - Compare mtimes of `.status.json` and the notebook file.
  - If sentinel says today but notebook has no session header for today: set `last_lapse_detected` with reason `"Tacitus sentinel-content drift YYYY-MM-DD — status reports last_reflection_time=HH:MM but no session header for today appears in the notebook. Tacitus' write did not land."`
  - Surface as the FIRST item in the audit output under `**Tacitus integrity:**`.

If sentinel says NOT-today, that is acceptable — Tacitus either didn't run yet or correctly left the sentinel unmoved after a [FAILURE] step. The audit reports "Tacitus did not run today" in that case.

### Layer 4: Brain catch-up trigger adds drift as hard-wrap step

`brain/current.md § On every session start` gains step #4 — read `.status.json` and the current-month notebook BEFORE acknowledging the user's first message; if drift is detected, hard-wrap the session and surface:

> "Tacitus' status sentinel reports a reflection at HH:MM today, but the notebook has no session header for today. This is the sentinel-content drift failure mode operating-protocols.md §16 was added to catch. Tacitus' write did not land. Want me to look at the actual run, restore from your hands if you have the substance, or skip and continue?"

Override via "skip" / "ignore drift" / "override" logs to `memory-change-log.md` and proceeds.

### Layer 5: lessons.md codifies the pitfall

New entry in `memory/essence/lessons.md`: **"Sentinel-without-content is a real failure family."** A status-of-X file is never authoritative on its own — it must be cross-checked against the artifact it purports to describe. Sentinels lie when they fall out of sync; content is truth. Generalizable beyond Tacitus: any time we add a status-sentinel file (`.status.json`, last-run markers, "completed" flags), we MUST also add an automatic check that confirms the sentinel's claim against the artifact.
