Passing CRLF to safe_write DOUBLE-translates and fails verify; pass LF, safe_write renders CRLF on disk.
- **Search scoring (state/search.ts::scoreClaim, per query token):** question +6 · subject +5 · topics +4 · answer_short +3 · answer/verbatim +1 · base +3 if subject⊆q. Matching is SUBSTRING (`includes`). **Routing (resolveQuery):** whole-query entity name/synonym → entity page; else askRanked + entityInQuery(phrase); if a claim's SUBJECT==the mentioned entity, `heroByIntent` re-heroes on the query minus the entity's own name. **also_about does NOT affect scoreClaim** — it only adds the claim to that entity's page (claimsForSubject) + can never hijack a "best answer" (the hero check is `best.subject===mentioned`). So topics = safe recall lever; subject = the routing/poison lever (leave it correct).
