## JUST SHIPPED (this session, on master): the SCANNER OCR actually works now.
Opening `dashboard/dashboard.html` **directly** (double-click, no launcher / no flag / no server) now
reads a label end-to-end. Verified on the real app both offline and online.

**The story:** the earlier "hang" had TWO layers. (1) A concurrency bug (two inputs at once double-
injected the engine) — fixed with a last-wins guard + a shared Tesseract load. (2) The REAL blocker,
which a new progress bar exposed: on `file://` the browser blocks `fetch()` of the local language
model, so the Tesseract worker never got its model and hung at "Load engine" forever.

**The fix (three parts):**
- **Bundled-model offline worker** — `dashboard/assets/vendor/tesseract/worker-offline.js` = model
  base64 + a `self.fetch` patch + the vendored `worker.min.js`, all in ONE file (loads via
  `importScripts`, which `file://` allows; no fetch). `state/ocr.ts` uses it on `file://` and the lean
  `worker.min.js` on http/https (no online bloat). It is **generated by `tools/build.mjs`** (idempotent)
  and **git-force-added (~16 MB)** — the `tesseract/` dir is gitignored, and a GitHub download only
  ships tracked files, so the offline-download case needs it committed.
- **Live progress indicator** (concept C, screenshot-approved) — `state/ocr` emits
  `lcscan:progress {stage,message,determinate,fraction}`; `views/scanner.renderScanning()` +
  `mount.onProgress` render staged pills (Prepare / Load engine / Read label) + a bar with the real %.
- **Fail-loud** — a reachability preflight (http only) + a 60 s timeout, and an honest error card + Try
  again instead of an infinite spinner.
