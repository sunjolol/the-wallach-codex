## The close-icon standard (A — established)
ONE canonical close: **`.ui-close` / `.ui-close--sm`** in `dashboard.css` (non-sealed). Search-popup
look (round, soft-shadow, 18px **SVG X** — never a text glyph), **ORANGE on hover** (`--ds-accent`).
Replaces 8+ ad-hoc × styles (`.vd-card__close`, `.rl-row__x`, `.vd-ocr__x`, `.gchip__x`,
`.scr-nav--close`, three `.kd-*__close`, `.ck-slot__trash`, a stray `.ds-icon-btn--close`). Design
system (`design-system.css`) is SEALED, so the standard lives in dashboard.css, not the DS.

## Regimen B — refinements round (2026-08-15, from Luneth's live testing)
- **Typeahead meta** — results now show "covers N of 90 essentials" (productSupplies via matchEssential
  on the vault entry's nutrients). #3 was worthless-to-a-layman with names only.
- **Removed** the redundant header "scan a label →" (bottom centered link covers it).
- **Centered** the bottom `.rr-scan` link (was inline-flex/left).
- **Scroll-overlap** — `.ck-rail .rail-panel` was `position: sticky` (shared rule); set `position: static`
  so the box + scan link scroll together (no sticky overlap). Same class of bug as the scanner rail.
- **#2 + the "I'm just browsing" bug (SAME root cause) FIXED** — `syncStackHeight` capped the active-stack
  box to `.ck-console` height, which is 0 while the Regimen tab is HIDDEN, so a re-render fired from
  another tab (scanner adopt → regimen:changed, or the goal veil's browse → saveRgUserGoals →
  regimen:changed) collapsed the box to 0px. Neutralised syncStackHeight (clears maxHeight; box grows
  naturally + scrolls with the page). Verified: box offsetHeight=264 after a hidden re-render, maxHeight=''.
